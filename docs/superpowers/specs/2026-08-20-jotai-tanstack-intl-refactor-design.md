# Refactor: Jotai + TanStack Query + react-router + react-intl

**Date:** 2026-08-20
**Scope:** Frontend of `claude-background` only. Server (`server/**`) and the transport layer (`src/lib/api.ts`) are unchanged.

## Problem

`src/App.tsx` (291 LOC) owns nearly all frontend state: auth, the chat list, the active chat id, lazy-loaded chat contents, a debounced PATCH queue via `useRef`, and a chain of `useEffect`s coordinating hydration. `useCourseJobs` (208 LOC) layers on top with ref-mirrored callbacks and an ad-hoc `AbortController` map, needed because closures inside its async loops otherwise see stale App state. Streaming updates mutate large `turns[]` arrays through nested state setters. Every server mutation is followed by a hand-written local-state update. There is no routing, so refresh loses the active chat, and no i18n scaffolding, so every user-visible string is a bare literal.

The refactor replaces this with three well-known primitives, each doing exactly what it's designed for:

- **TanStack Query** owns server-of-record data (auth status, chat list, per-chat records, course intake).
- **Jotai** owns working state (per-chat live document, in-flight course jobs, locale) and hydration from Query.
- **react-router** owns "which chat is active" so the URL becomes the source of truth.
- **react-intl** wraps every static UI string so the app is translation-ready.

## Non-goals

- No changes to `server/**` or `src/lib/api.ts`.
- No test suite in this refactor (the repo has none today; deferred).
- No React Query persistence to `localStorage`, no devtools bundled by default.
- No RTL support, no locale switcher UI, no server-side locale storage.
- No translation of model-generated content (chat turns, course modules/resources, quiz text, web-search sources, LLM-generated intake questions).
- No changes to the visual design of any component.

## Dependencies

Add:

- `jotai`
- `@tanstack/react-query`
- `react-router-dom`
- `react-intl`
- `@formatjs/cli` (dev)

Remove: none. `useCourseJobs.ts` is deleted; no packages to drop.

## State topology

### Server-of-record (Query)

Only three read queries and their invalidation rules:

| Query key | Source | Invalidated by |
| --- | --- | --- |
| `['auth']` | `getAuthStatus()` | `login`, `signup`, `signOut` mutations |
| `['chats']` | `listChats()` | `createChat`, `deleteChat`, `patchChat` mutations (the last one via `setQueryData` to keep the sidebar sort fresh) |
| `['chat', id]` | `fetchChat(id)` | `patchChat` (via `setQueryData` after the debounced save resolves) |

There is no `useQuery` for anything streamed. Course intake (`fetchCourseIntake(topic)`) is deliberately *not* a query — it's fetched imperatively inside `startCourseJob` under the job's own `AbortController`, matching today's per-job semantics. A `useQuery(['intake', topic])` would cache across job starts and complicate abort composition; the tradeoff isn't worth it for a single call per job.

### Working state (Jotai)

- **`authAtom`** — derived read-only atom that mirrors `useAuth().data`. Components that only need the login state read this instead of the query.
- **`chatIdsAtom`** — ordered id list; mirrors `useChatList().data` sort.
- **`sidebarEntriesAtom`** — derived atom the sidebar actually reads. Overlays `courseJobFamily` placeholder entries on top of `chatIdsAtom`, so an in-flight course still shows up as a row titled `Course · <topic>` (matching today's `beginCourse` behavior) *and* as a job chip. Ordering: placeholders sort by their `createdAt` alongside real chats. When the job completes, the placeholder row disappears at the same moment the real chat row appears via `['chats']` cache update.
- **`chatFamily(id)`** — one atom per chat holding `{ id, title, turns, offers, loaded }`. On first read `useChat(id)` runs a `useQuery`, and a `useHydrateAtoms`-style effect seeds the atom with the fetched record. After that, the atom is authoritative; the query stays only for background refetch on window focus / reconnect.
- **`courseJobFamily(id)`** — one atom per in-flight course job holding the same shape today's `CourseJob` uses. Populated by `startCourseJob(id, topic)`; cleared by `cancelCourseJob(id)` or on stream completion.
- **`localeAtom`** — a plain primitive atom holding the BCP-47 tag; initialized from `navigator.language`, falls back to `'en'` if unmatched.

### Streams write to atoms directly

- `streamChatToAtom(id, messages, webSearch, signal)` iterates `streamChat()` and appends into `chatFamily(id).turns` on each SSE event. It optimistically appends the user turn before opening the request.
- `runCourseGeneration(id, topic, answers, signal)` iterates `generateCourse()` and writes phase / syllabus / module-done into `courseJobFamily(id)`. On the terminal `chat` event, it deletes the job atom and seeds `chatFamily(newId)` with the returned record.

Both functions are plain module-level functions, not hooks. They receive the Jotai store (via `useStore()` at the call site) and the query client (via `useQueryClient()`) so they can be composed without hook rules.

### Debounced save = one Jotai effect

`store/saveEffect.ts` mounts a single subscription that:

1. On any change to a `chatFamily(id)` where `{ title | turns | offers }` differs from the last-saved snapshot,
2. Coalesces changes for that id inside a 700ms window,
3. Fires `patchChat(id, patch)` via the mutation defined in `useChatMutations`,
4. On success, calls `setQueryData(['chats'], …)` to bump `updatedAt` so the sidebar re-sorts,
5. On failure, keeps the local atom as-is and drops the pending patch (the next change re-schedules a full-payload save — same behavior as today).

This replaces the `useRef<Map<string, Timeout>>` in `App.tsx`.

### Course jobs — end of `useCourseJobs`

The current hook exists to keep in-flight generation alive across sidebar navigation and to work around stale-closure problems. Under Jotai:

- Job state lives in `courseJobFamily(id)`, which persists regardless of what's mounted.
- `AbortController`s live in a module-scoped `Map<string, AbortController>` in `store/courseJobs.ts`.
- `startCourseJob` / `cancelCourseJob` are plain functions callable from anywhere; they read/write atoms via the passed-in Jotai store handle.
- Completion is signaled by atom state, not a callback. `ChatRoute` observes both `chatFamily(id)` and `courseJobFamily(id)`; if the job exists, it renders the wizard; if it doesn't, it renders the chat.

**Placeholder-id → real-id handoff.** `beginCourse` mints a `crypto.randomUUID()` placeholder id (as today), and the URL becomes `/chats/<placeholderId>` during generation. The server returns a *different* real id in the terminal `chat` NDJSON event. `runCourseGeneration` handles the swap in one atomic step:

1. Seed `chatFamily(newRealId)` with the returned record.
2. Delete `courseJobFamily(placeholderId)` and the placeholder row (its sidebar entry disappears via `sidebarEntriesAtom`, replaced by the real chat's row when `['chats']` is invalidated).
3. If `window.location.pathname === '/chats/' + placeholderId`, call `router.navigate('/chats/' + newRealId, { replace: true })`. If the user has navigated away, leave their route alone — matches today's `onReady` behavior of "only follow the user if they were still on the placeholder."

The navigate call uses the router instance directly (imported from a module holding `createBrowserRouter`'s return value) so this logic can live in a plain function outside React.

The former `onReady` / `onCancelled` callbacks disappear. `IndexRedirect` and `ChatRoute` react to atom changes directly.

## Routing

`react-router-dom` v6+ (`createBrowserRouter` + `RouterProvider`).

| Path | Component | Behavior |
| --- | --- | --- |
| `/` | `IndexRedirect` | Redirects to `/chats/<newest-id>`. If the chat list is empty, calls `createChat` mutation and redirects to the new id. |
| `/chats/:id` | `ChatRoute` (child of `Root`) | Renders `<CourseWizard/>` when `courseJobFamily(id)` has an entry, otherwise `<Chat/>`. If neither `chatFamily(id)` nor `courseJobFamily(id)` exists (e.g., the id was just deleted, or an unknown id in the URL), redirects to `/`. |
| `/signin` | `SignInRoute` | Rendered when `authAtom.authenticated === false`; other routes redirect here via a loader/guard. |

**Delete flow.** `deleteChat` mutation's `onMutate` removes the id from `chatIdsAtom` optimistically. On success, if the deleted id equals the current route param, `router.navigate('/', { replace: true })` — `IndexRedirect` then handles the empty-list case (create a fresh chat and redirect to it) or picks the newest remaining chat. This reproduces today's behavior of `removeChat` (optimistic drop + fallback-to-first + auto-create-if-empty) without threading state through App.

`Root` is a layout route containing the app header, sidebar, and an `<Outlet/>`. Sidebar entries become `<Link>`s to `/chats/:id`. The course wizard is *not* its own route — the URL for a chat is stable whether the wizard or the chat is showing.

## i18n

### Provider stack

`main.tsx`:

```
QueryClientProvider
  Jotai Provider
    IntlProvider (subscribes to localeAtom; loads compiled catalog for that locale)
      BrowserRouter
        App
```

`IntlProvider` (custom wrapper in `src/i18n/IntlProvider.tsx`) reads `localeAtom`, dynamically imports the matching `src/i18n/compiled/<locale>.json`, and passes messages to `<IntlProvider>` from `react-intl`. Loading state is a bare div until the catalog resolves.

### In-scope literals (concrete)

- `App.tsx` header: `"claude-background"` brand, `"signed in as {username}"`, `"Sign out"`, `"Loading…"`.
- `Sidebar`: "New chat", chat row action labels, empty state, "Generating…" job labels.
- `SignIn`: form labels, buttons, error banners produced client-side.
- `CourseWizard`: stage headings ("Generating a course on", "A few questions to tailor this", etc.), submit/cancel labels, progress copy, error state.
- `LearnPanel`: section headings, "Read", "Watch", "Practice", "Quiz", empty states.
- `Chat`: composer placeholder, send/stop buttons, thinking-block toggle, "sources" label, streaming error banner.
- `titleFromPrompt` fallback `"New chat"`.
- `<FormattedRelativeTime>` for chat-row timestamps (currently shown as a raw number).

### Out of scope (stays untranslated)

- Any content streamed from the model: assistant text, thinking, course modules, resources, quiz text, background research output, web-search sources.
- Server-returned error strings (from `readError` in `api.ts`). Localizing them would require server changes; kept as-is per non-goals.
- README, `.env.example`, and other dev-facing text.

### Extraction pipeline

Two new `package.json` scripts:

- `i18n:extract` — `formatjs extract 'src/**/*.{ts,tsx}' --out-file src/i18n/messages/en.json --id-interpolation-pattern '[sha512:contenthash:base64:6]'`
- `i18n:compile` — `formatjs compile src/i18n/messages/en.json --out-file src/i18n/compiled/en.json`

IDs are auto-generated content hashes; there are no hand-named message IDs. `defineMessages` blocks live in the component file that uses them.

## Data flow example: user sends a message

1. `Chat.tsx` composer calls `sendMessage(chatId, text)` (from `streams/streamChatToAtom.ts`), passing the Jotai store handle.
2. `sendMessage` appends the user turn to `chatFamily(chatId).turns` immediately (optimistic). If this is the first user turn in the chat (`turns.length === 0` before appending), it also writes `title = titleFromPrompt(text)` into the same atom — replaces today's `onFirstUserMessage` → `setTitle` → `queueSave` path.
3. It opens the SSE stream via `streamChat()` and iterates; each event mutates the atom in place (assistant text appended, thinking, `background`, `search`, `citation`, etc.).
4. `saveEffect` observes the atom change and schedules a 700ms debounced `patchChat` (covering `title`, `turns`, and `offers` together — one PATCH per debounce window).
5. On the `done` event, `sendMessage` marks the assistant turn complete in the atom. The debounced save picks up the final state and PATCHes.
6. On save success, `setQueryData(['chats'], …)` bumps `updatedAt` (and `title` if it changed) so the sidebar re-sorts and re-labels.

## Error handling

Same user-visible behavior as today, different plumbing:

- **Query errors** surface via `useQuery({...}).error`. Sidebar/header show an inline banner; retries via TanStack Query's default retry policy.
- **Mutation errors** for `patchChat` are swallowed by `saveEffect` (the next atom change retries the full payload — identical to today's comment: "transient — next save will retry the whole payload").
- **Stream errors** (`ChatEvent.type === "error"` or thrown from the generator) are appended to the chat atom as an error turn, matching the current behavior in `Chat.tsx`.
- **Auth errors** on any mutation invalidate `['auth']`, which flips `authAtom.authenticated` to false and the route guard redirects to `/signin`.
- **Course-generation errors** land in `courseJobFamily(id).stage = 'error'` with a message; the wizard already renders this branch.

## Migration order

Each step leaves the app runnable. Verify by running `npm run dev` and exercising the changed area.

1. **Providers & routing shell.** Add deps. Wrap `main.tsx` with `QueryClientProvider` + Jotai `Provider` + `IntlProvider` (with an empty message catalog) + `BrowserRouter`. Convert `App.tsx` to render existing components under a single `/` route so nothing visibly changes yet.
2. **i18n scaffolding.** Add `IntlProvider.tsx`, `localeAtom`, empty `messages/en.json`, and the extract/compile scripts. Verify nothing regresses.
3. **REST → Query.** Move `getAuthStatus` / `listChats` / `fetchChat` / `fetchCourseIntake` into `queries/`. Move `login` / `signup` / `signOut` / `createChat` / `deleteChat` / `patchChat` into `mutations/`. Update `App.tsx` to consume them; delete the corresponding `useEffect`s.
4. **`chatFamily` + hydration.** Introduce `chatFamily(id)` and `useChat(id)`. Update `Chat.tsx` to read/write the atom. Convert `streamChat` call sites to `streamChatToAtom`. Delete the `turns`/`offers` fields from `App.tsx`.
5. **`saveEffect`.** Introduce and mount it in `Root`. Delete the `useRef`-backed debounce Map from `App.tsx`.
6. **`courseJobFamily`.** Introduce it and `runCourseGeneration`. Migrate `CourseWizard.tsx` and `App.tsx` off `useCourseJobs`. Delete `useCourseJobs.ts`.
7. **Routing proper.** Add `Root` / `IndexRedirect` / `ChatRoute` / `SignInRoute`; convert Sidebar entries to `<Link>`s; strip remaining state from `App.tsx`.
8. **i18n wrap.** Wrap every in-scope literal in `<FormattedMessage>` / `intl.formatMessage`. Run `i18n:extract` and `i18n:compile`. Commit the generated catalog.
9. **Cleanup.** Delete dead code; run `npm run typecheck` and `npm run lint`.

## Risks and mitigations

- **Streaming performance.** Appending to a large `turns[]` on every SSE chunk is already the shape today; moving it into an atom does not change complexity. Jotai's atom-per-chat topology keeps re-renders scoped to the active chat view.
- **Query ↔ atom drift.** Hydration is one-way (query → atom) and only on first mount for a given id. `patchChat`'s response also updates `setQueryData(['chat', id], …)` to keep the two aligned for background refetches. If a background refetch would clobber unsaved atom state, the atom wins (the effect schedules another save).
- **Router in a preview iframe.** `BrowserRouter` needs history API access; this is fine in the Vite dev server. If someone later serves the SPA from a subpath, `basename` will need setting.
- **i18n key churn.** Auto-hashed IDs change when copy changes; that's the intended behavior — translations get invalidated when source copy changes. No renaming discipline required.
